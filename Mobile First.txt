Mobile First — Here's Why, Definitively
Build mobile first. No debate. Here is the reasoning across every axis:
The killer features that make Savora differentiated — hands-free gesture cooking, camera OCR, voice dictation, pantry scanner, and wake-lock cooking mode — are all physically impossible on a web app. If you build web first, you're building a worse version of a product that has no competitive advantage. Every hour on a web MVP is an hour spent building the version that doesn't win.
You already have Flutter in your stack from Tawfir. You are not starting from zero. The backend (Django + DRF + Channels) is identical regardless of which client you build first, so your real question is only about the client — and Flutter gives you iOS + Android simultaneously.
The web app comes later as a companion: a recipe importer browser extension, a landing page, and an account management portal. That's its role. The mobile app is the product.
Start order within mobile: Build Android first (faster iteration cycle, no Apple developer account friction, you can sideload APKs for demos), then submit to both stores simultaneously when you're ready.

SECTION 1 — PRODUCT IDENTITY & BRAND PHILOSOPHY
App Name: SavoraSavora
Tagline: Cook smarter. Waste less. Eat better.
Design Movement Name: "Culinary Modernism"
Philosophy:
Savora sits at the intersection of warm human ritual and cold machine intelligence. The visual language must never feel clinical or sterile like a health-tracking app, nor rustic and artisanal like a food blog. It occupies a third space: warm precision. The kind of kitchen that has beautiful wooden countertops, a Le Creuset Dutch oven, and a Raspberry Pi running on the shelf.
Every surface breathes. Generous white space is the primary design element — not because of minimalism as a trend, but because cooking is already visually chaotic, and the app must be the calm in that storm. When a user's hands are covered in flour, the interface must be readable at a glance from 60cm away.
The color system is built around earth tones elevated by one sharp modern accent. Think warm cream backgrounds, deep espresso text, terracotta mid-tones — then a single electric green or saffron accent that signals AI intelligence without screaming "tech startup."
Typography is the soul of the app. Display text should feel editorial — like a high-end food magazine, not a recipe card website. Body text must be supremely readable in low kitchen light.

SECTION 6 — DARK MODE SPECIFICATION
All screens have a dark mode variant. Rules:
Map light tokens to dark equivalents:
--bg-primary     → #1C1814   (espresso, not pure black)
--bg-secondary   → #242018   (slightly lighter, cards)
--bg-tertiary    → #2E2822   (elevated surfaces)
--surface-card   → #2A2420   (cards on dark bg)
--border-subtle  → #3A332D   (subtle borders)
--border-strong  → #4A4038   (input borders)
--text-primary   → #F5F0E8   (warm off-white, not pure white)
--text-secondary → #9C8B7E   (unchanged — works on both)
--text-tertiary  → #6B5E52   (unchanged)

Accent colors remain the same. They're saturated enough to pop on both.

AI badge dark mode:
--ai-bg    → #1A2E22   (dark green, not light sage)
--ai-text  → #3DBE6C   (unchanged)
Cooking mode is always dark (this is intentional — it never changes).

RECIPE CARD SAVE (bookmark tap)
  Icon bounces with spring curve (ease-spring, 250ms)

  Particle burst: 6 small dots explode outward and fade (200ms)

FAB OPEN
  FAB scales to 1.05 on tap (80ms), back to 1.0 (80ms)
  Bottom sheet rises with ease-decelerate (350ms)
  Background dims: opacity 0→0.4 overlay (350ms)
  FAB icon rotates 45° to become "×" (200ms, ease-standard)

RECIPE IMPORT COMPLETE
  Card "falls" from top of screen into the cookbook (300ms)
  Scale: 0.6→1.0 with spring, opacity 0→1
  Cookbook icon in nav bar briefly bounces

PANTRY ITEM ADD
  Ingredient chip "flies" from pantry to recipe card (if adding from recipe detail)
  Green check materializes on ingredient row

COOKING MODE — STEP TRANSITION
  Next: current step slides left, new step slides in from right (200ms, ease-standard)
  Previous: reverse direction
  Voice trigger: adds a quick white flash overlay (80ms) before slide

STEP COMPLETION
  User can swipe right on a step to mark as done
  Step text gets strikethrough animation (left-to-right line draw, 300ms)
  Next step highlight pulses once

TIMER RING
  Device vibrates in pattern: long, short, long
  Screen flashes warm amber three times
  Toast notification persists until dismissed (unlike normal toasts)

SECTION 8 — PLATFORM-SPECIFIC IMPLEMENTATION NOTES
Flutter Implementation Notes:
FONTS
  Add to pubspec.yaml:
    google_fonts: ^6.x
  Use: GoogleFonts.fraunces(), GoogleFonts.dmSans(), GoogleFonts.dmMono()
  Or: Bundle as local assets (better for offline-first)

STATE MANAGEMENT
  Use flutter_riverpod for global state
  Use flutter_bloc for complex flow states (import flow state machine)

LOCAL DATABASE (offline-first)
  Use isar for the local recipe database
  Sync strategy: local-first, background sync to Django API
  User should see their recipes immediately, even offline

WAKE LOCK (cooking mode)
  Package: wakelock_plus
  Activate on entering cooking mode, release on exit

GESTURES
  Use google_mlkit_face_mesh for on-device gesture detection
  Run on isolate to not block UI thread

BOTTOM NAVIGATION
  Use go_router for navigation
  Bottom nav persists across tab switches (no re-render)
  Use IndexedStack to maintain tab state

ANIMATIONS
  Use flutter_animate package (wraps AnimationController boilerplate)
  Import animations package for Material motion transitions

HAPTICS
  HapticFeedback.lightImpact() for most interactions
  HapticFeedback.mediumImpact() for saves and completions
  HapticFeedback.heavyImpact() for timer ring

SAFE AREAS
  Wrap all screens with SafeArea widget
  Bottom padding: MediaQuery.of(context).padding.bottom + kBottomNavigationBarHeight
